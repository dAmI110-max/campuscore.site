Campus Core is a real commercial, university-agnostic student ecosystem, not a static demo. It must not be restricted to UNIOSUN.

**Why:** The user explicitly specified a production product for students from multiple universities and countries.

**How to apply:** Start with sourced Nigerian university records, retain scalable country/institution/faculty/department relationships, and mark incomplete directory coverage openly. Never invent official academic records.

Do not fabricate users, sellers, listings, properties, employers, messages, members, attendance, engagement, analytics, transactions or financial balances. Empty states and unavailable integrations must be honest.

**Why:** The user's specification makes real data only a strict production requirement.

**How to apply:** Any test fixtures must remain isolated from real user-facing content. Do not add attractive example listings to fix an empty screen.

Prioritize a secure working core over superficial breadth. Do not call a release production-ready until actual signed-in and deployed journeys are verified. No wallets, escrow or real-money payments without reviewed and tested financial controls.

**Why:** The user's definition of done explicitly requires real test results, launch blockers and deployed-journey verification.

**How to apply:** Distinguish implementation from verification in status reports; retain disabled-state honesty for integrations and incomplete modules.

Roommate Finder must protect private contact details and precise accommodation
addresses. Compatibility is based on declared preferences, not a guarantee of
safety or successful cohabitation.

**Why:** The user's production-readiness specification explicitly requires
privacy controls and transparent, qualified compatibility matching.

**How to apply:** Use coarse campus/area information, authenticated discovery
and mutual-interest contact flows; do not add public phone/address fields or
claim students or accommodation are safety-certified.
